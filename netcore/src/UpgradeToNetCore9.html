Kế hoạch nâng cấp dự án External Accounting Website lên .NET Core 9

Dự án hiện tại đang sử dụng .NET Framework 4.7.2. Mục tiêu là chuyển đổi và nâng cấp lên .NET Core 9.

1. Đánh giá và Lập kế hoạch

  • 1.1. Phân tích cấu trúc dự án: Xác định các project, dependencies, và cách chúng tương tác.
  • 1.2. Kiểm tra tương thích Dependency: Liệt kê tất cả các gói NuGet, thư viện bên thứ ba và các API không phải của Microsoft. Kiểm tra xem chúng có phiên bản tương thích với .NET Core/NET 9 hay không. Sử dụng công cụ như .NET Portability Analyzer.
  • 1.3. Phân tích mã nguồn: Xác định các đoạn mã sử dụng các API chỉ có trong .NET Framework (ví dụ: System.Web, Enterprise Library). Lên kế hoạch thay thế hoặc refactor các đoạn mã này.
  • 1.4. Ước tính nguồn lực: Đánh giá thời gian, nhân lực và chi phí cần thiết cho quá trình chuyển đổi.

2. Chuyển đổi định dạng Project (.csproj)

  • 2.1. Sao lưu dự án: Luôn sao lưu toàn bộ dự án trước khi thực hiện bất kỳ thay đổi lớn nào.
  • 2.2. Chuyển đổi thủ công hoặc tự động:
    • Sử dụng try-convert tool hoặc .NET Upgrade Assistant để tự động chuyển đổi định dạng .csproj sang SDK-style.
    • Nếu chuyển đổi thủ công, tạo file .csproj mới với định dạng SDK-style và di chuyển các references, item groups.
  • 2.3. Cập nhật TargetFramework: Thay đổi v4.7.2 thành net9.0.
  • 2.4. Xóa bỏ các file không cần thiết: Loại bỏ các file như packages.config (NuGet sẽ quản lý trực tiếp trong .csproj).

3. Cập nhật các gói NuGet và Thư viện

  • 3.1. Nâng cấp các gói tương thích: Sử dụng NuGet Package Manager hoặc lệnh dotnet add package [PackageName] để nâng cấp các gói hiện có lên phiên bản mới nhất hỗ trợ .NET Core/NET 9.
  • 3.2. Thay thế các thư viện không tương thích:
    • Tìm kiếm các thư viện thay thế cho .NET Core cho các gói không tương thích (ví dụ: Entity Framework 6 sang Entity Framework Core, ASP.NET Web API sang ASP.NET Core Web API).
    • Sử dụng các phiên bản mới của Microsoft libraries (ví dụ: Microsoft.Extensions.*).
  • 3.3. Giải quyết xung đột Dependency: Xử lý các lỗi do xung đột phiên bản giữa các gói.

4. Chuyển đổi Cấu hình

  • 4.1. Di chuyển Web.config sang appsettings.json:
    • Chuyển đổi các phần tử cấu hình như connection strings, app settings sang file appsettings.json.
    • Tạo các file cấu hình theo môi trường (appsettings.Development.json, appsettings.Production.json).
  • 4.2. Cấu hình biến môi trường và Secret: Sử dụng User Secrets cho môi trường phát triển và các giải pháp quản lý secret khác cho môi trường sản xuất.
  • 4.3. Sử dụng API cấu hình mới: Tích hợp cấu hình vào Program.cs hoặc Startup.cs sử dụng IConfiguration.

5. Điều chỉnh Mã nguồn (Refactoring)

  • 5.1. Cấu trúc ứng dụng:
    • Tạo file Program.cs và Startup.cs (hoặc sử dụng Minimal APIs trong .NET 6+).
    • Cấu hình Middleware và Dependency Injection.
  • 5.2. Thay thế API:
    • Thay thế System.Web.* bằng các tương đương trong Microsoft.AspNetCore.*.
    • Cập nhật các phần liên quan đến File I/O, Networking để tương thích với .NET Core.
    • Điều chỉnh Authentication và Authorization để sử dụng Identity trong ASP.NET Core.
  • 5.3. Xử lý lỗi và Logging: Cập nhật hệ thống logging sang Microsoft.Extensions.Logging.
  • 5.4. Async/Await: Đảm bảo sử dụng async/await một cách nhất quán và hiệu quả.

6. Di chuyển Thành phần UI (nếu có)

  • 6.1. ASP.NET MVC cũ sang ASP.NET Core MVC/Razor Pages:
    • Chuyển đổi Views (.cshtml) để tương thích với cú pháp Razor của ASP.NET Core.
    • Di chuyển Controllers và Models.
    • Nếu sử dụng Web Forms, cân nhắc chuyển đổi sang Razor Pages hoặc một frontend framework hiện đại (React, Angular, Vue) với Web API backend.
  • 6.2. Cập nhật Static Files: Đảm bảo các file CSS, JavaScript, hình ảnh được phục vụ đúng cách thông qua Middleware UseStaticFiles.
  • 6.3. Client-side Libraries: Nâng cấp hoặc thay thế các thư viện JavaScript/CSS lỗi thời.

7. Cập nhật CI/CD

  • 7.1. Cập nhật Build Agents: Đảm bảo các build agent hoặc môi trường CI/CD có cài đặt .NET 9 SDK.
  • 7.2. Điều chỉnh Build Script: Thay đổi các lệnh build từ MSBuild hoặc .NET Framework-specific commands sang dotnet build, dotnet publish.
  • 7.3. Cập nhật Deployment Strategy: Tùy chỉnh quy trình deploy để phù hợp với ứng dụng .NET Core (ví dụ: containerization với Docker, triển khai lên Azure App Service/AWS Elastic Beanstalk).
  • 7.4. Cấu hình Testing trong CI: Đảm bảo các bài kiểm thử được chạy tự động trong pipeline CI/CD.

8. Kiểm thử Toàn diện

  • 8.1. Kiểm thử đơn vị (Unit Test): Đảm bảo tất cả các unit test cũ hoạt động và viết thêm test cho các đoạn mã mới hoặc được refactor.
  • 8.2. Kiểm thử tích hợp (Integration Test): Kiểm tra sự tương tác giữa các thành phần của ứng dụng và với các dịch vụ bên ngoài (database, API khác).
  • 8.3. Kiểm thử hệ thống (System Test): Kiểm tra toàn bộ ứng dụng trong môi trường gần giống sản phẩm.
  • 8.4. Kiểm thử hiệu năng (Performance Test): Đánh giá hiệu suất của ứng dụng sau khi nâng cấp.
  • 8.5. Kiểm thử bảo mật (Security Test): Đảm bảo ứng dụng vẫn an toàn và tuân thủ các quy tắc bảo mật.

9. Các lưu ý quan trọng và Lời khuyên

  • 9.1. Thực hiện từng bước nhỏ: Tránh cố gắng nâng cấp tất cả cùng lúc. Thực hiện từng project một, từng module một.
  • 9.2. Sử dụng công cụ hỗ trợ: Tận dụng tối đa .NET Upgrade Assistant và .NET Portability Analyzer.
  • 9.3. Tham khảo tài liệu: Luôn tham khảo tài liệu chính thức của Microsoft về việc nâng cấp từ .NET Framework lên .NET Core/NET 9.
  • 9.4. Kiểm soát phiên bản: Sử dụng hệ thống kiểm soát phiên bản (Git) một cách hiệu quả, tạo các branch riêng cho quá trình nâng cấp.
  • 9.5. Đào tạo đội ngũ: Đảm bảo đội ngũ phát triển có kiến thức về .NET Core/NET 9.
