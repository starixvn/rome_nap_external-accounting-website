Báo cáo phân tích chi tiết dự án External Accounting Website

Mục tiêu: Nâng cấp từ .NET Framework 4.7.2 lên .NET Core 9

Ngày phân tích:

1. Tổng quan cấu trúc dự án

1.1. Danh sách các Project chính

Project Name Type Target Framework Dependencies Priority

Core Class Library .NET Framework 4.7.2 Core.Shared, DataAccess, Service, DTO Critical
Core.Shared Class Library .NET Framework 4.7.2 Minimal dependencies Low
Fanex.ExternalAccount.Controllers Class Library (MVC Controllers) .NET Framework 4.7.2 Core, Service, DTO, ViewModel Critical

Fanex.ExternalAccount.Service Class Library (Business Logic) .NET Framework 4.7.2 DataAccess, DTO, ViewModel Critical

2. Phân tích Dependencies và Packages

2.1. Microsoft Enterprise Library (VẤN ĐỀ NGHIÊM TRỌNG)

Cảnh báo: Dự án sử dụng Microsoft Enterprise Library 5.0.414.0 - một thư viện cũ không tương thích với .NET Core.
  • Microsoft.Practices.EnterpriseLibrary.Caching - Cần thay thế bằng Microsoft.Extensions.Caching.Memory
  • Microsoft.Practices.EnterpriseLibrary.Data - Cần thay thế bằng Entity Framework Core hoặc Dapper
  • Microsoft.Practices.EnterpriseLibrary.Logging - Cần thay thế bằng Microsoft.Extensions.Logging
  • Microsoft.Practices.Unity - Cần thay thế bằng Microsoft.Extensions.DependencyInjection

2.2. ASP.NET MVC Framework

Chú ý: Dự án sử dụng ASP.NET MVC 5.2.6 - cần nâng cấp lên ASP.NET Core MVC.
  • System.Web.Mvc → Microsoft.AspNetCore.Mvc
  • System.Web.Razor → Microsoft.AspNetCore.Razor
  • System.Web.Helpers → Microsoft.AspNetCore.Mvc.Rendering

2.3. Các thư viện tương thích

Tốt: Một số thư viện đã tương thích với .NET Core.
  • Newtonsoft.Json 13.0.3 - Tương thích
  • Dapper 2.1.35 - Tương thích
  • MessagePack 3.1.1 - Tương thích
  • StackExchange.Redis 2.8.24 - Tương thích
  • NPOI 2.6.1 - Tương thích

2.4. Các thư viện cần kiểm tra

Cần kiểm tra: Một số thư viện cần xác minh tương thích.
  • Fanex.* - Các thư viện nội bộ, cần kiểm tra source code
  • ONEbook.UM 3.1.1 - Cần kiểm tra phiên bản .NET Core
  • RestSharp 105.2.3 - Cần nâng cấp lên phiên bản mới
  • FluentValidation 3.2.0.0 - Cần nâng cấp lên phiên bản mới

3. Phân tích từng Module chi tiết

3.1. Fanex.ExternalAccount.UI (Web Application)

Độ phức tạp: CAO - Đây là project chính cần nâng cấp nhiều nhất.
  • Global.asax.cs → Cần chuyển đổi sang Program.cs và Startup.cs
  • Web.config → Cần chuyển đổi sang appsettings.json
  • Areas/ - Cần cập nhật cấu trúc Areas cho ASP.NET Core
  • Views/ - Cần cập nhật Razor syntax
  • Scripts/ - Cần cập nhật bundling và minification

3.2. Core Module

Độ phức tạp: TRUNG BÌNH - Cần thay thế Enterprise Library.
  • Authorization/ - Cần cập nhật cho ASP.NET Core Identity
  • Context/ - Cần cập nhật HttpContext usage
  • Filters/ - Cần chuyển đổi sang ASP.NET Core Filters
  • Configurations/ - Cần cập nhật configuration system

3.3. DataAccess Module

Độ phức tạp: CAO - Cần thay thế hoàn toàn Enterprise Library Data.
  • Criteria/ - 140 files cần cập nhật database access
  • Customer/ - Cần cập nhật repository pattern
  • Report/ - Cần cập nhật reporting logic
  • UserControl/ - Cần cập nhật user management

3.4. Service Module

Độ phức tạp: TRUNG BÌNH - Cần cập nhật dependency injection.
  • Customer/ - Business logic services
  • Report/ - Reporting services
  • UserControl/ - User management services
  • TelegramBot/ - External service integration

3.5. Controllers Module

Độ phức tạp: TRUNG BÌNH - Cần cập nhật cho ASP.NET Core MVC.
  • Authentication/ - Cần cập nhật authentication logic
  • Customer/ - Customer management controllers
  • Report/ - Reporting controllers
  • UserControl/ - User management controllers

4. Kế hoạch nâng cấp chi tiết theo từng bước

4.1. Giai đoạn 1: Chuẩn bị và Setup (1-2 tuần)

  • Bước 1.1: Tạo solution mới với .NET 9
  • Bước 1.2: Tạo các project mới với SDK-style format
  • Bước 1.3: Setup dependency injection container
  • Bước 1.4: Setup logging system
  • Bước 1.5: Setup configuration system

4.2. Giai đoạn 2: Core Libraries (2-3 tuần)

  • Bước 2.1: Nâng cấp Core.Shared (ít dependencies nhất)
  • Bước 2.2: Nâng cấp DTO project
  • Bước 2.3: Nâng cấp Utility project
  • Bước 2.4: Nâng cấp ViewModel project

4.3. Giai đoạn 3: Data Layer (3-4 tuần)

  • Bước 3.1: Thay thế Enterprise Library Data bằng Dapper/EF Core
  • Bước 3.2: Cập nhật tất cả Criteria classes
  • Bước 3.3: Cập nhật Repository pattern
  • Bước 3.4: Cập nhật connection string management

4.4. Giai đoạn 4: Business Logic (2-3 tuần)

  • Bước 4.1: Nâng cấp Service project
  • Bước 4.2: Cập nhật dependency injection
  • Bước 4.3: Cập nhật caching mechanism
  • Bước 4.4: Cập nhật logging calls

4.5. Giai đoạn 5: Web Layer (3-4 tuần)

  • Bước 5.1: Nâng cấp Controllers project
  • Bước 5.2: Cập nhật authentication/authorization
  • Bước 5.3: Cập nhật filters và middleware
  • Bước 5.4: Nâng cấp UI project
  • Bước 5.5: Cập nhật Views và Razor syntax

4.6. Giai đoạn 6: Testing và Deployment (2-3 tuần)

  • Bước 6.1: Unit testing
  • Bước 6.2: Integration testing
  • Bước 6.3: Performance testing
  • Bước 6.4: Security testing
  • Bước 6.5: Deployment và monitoring

5. Ước tính thời gian và nguồn lực

5.1. Thời gian tổng thể

  • Tổng thời gian: 13-19 tuần (3-4.5 tháng)
  • Thời gian phát triển: 11-16 tuần
  • Thời gian testing: 2-3 tuần

5.2. Nguồn lực cần thiết

  • Senior .NET Developer: 1 người (full-time)
  • Mid-level .NET Developer: 1-2 người (full-time)
  • QA Tester: 1 người (part-time)
  • DevOps Engineer: 1 người (part-time)

5.3. Rủi ro và thách thức

Rủi ro cao:
  • Enterprise Library migration phức tạp
  • Custom Fanex libraries có thể không tương thích
  • Database schema có thể cần thay đổi
  • Third-party integrations cần cập nhật

6. Khuyến nghị và lời khuyên

6.1. Khuyến nghị kỹ thuật

  • Bắt đầu với .NET 8 thay vì .NET 9 để ổn định hơn
  • Sử dụng .NET Upgrade Assistant để tự động hóa một phần quá trình
  • Tạo migration plan chi tiết cho từng module
  • Thiết lập CI/CD pipeline ngay từ đầu

6.2. Khuyến nghị quản lý

  • Chia nhỏ thành các milestone để dễ theo dõi tiến độ
  • Thiết lập backup strategy cho code và database
  • Đào tạo team về .NET Core trước khi bắt đầu
  • Lập kế hoạch rollback trong trường hợp có vấn đề

6.3. Các bước tiếp theo

  1. Phê duyệt kế hoạch và ngân sách
  2. Thiết lập môi trường phát triển
  3. Bắt đầu với Core.Shared project
  4. Thiết lập automated testing
  5. Bắt đầu migration theo kế hoạch

7. Kết luận

Việc nâng cấp dự án External Accounting Website từ .NET Framework 4.7.2 lên .NET Core 9 là một dự án lớn và phức tạp, đòi hỏi:

  • Thời gian: 3-4.5 tháng
  • Nguồn lực: 2-3 developers + QA + DevOps
  • Rủi ro: Trung bình đến cao
  • Lợi ích: Performance, security, maintainability tốt hơn
Khuyến nghị: Nên thực hiện dự án này để đảm bảo ứng dụng có thể tiếp tục phát triển và bảo trì trong tương lai.
